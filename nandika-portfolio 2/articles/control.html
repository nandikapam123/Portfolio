Closed-Loop Control and Robot Localization: A Practical Notebook

A measurement-first guide to feedback loops, state estimation, calibration, and meaningful performance graphs for mobile robots.

Research and technical article

System model and feedback

A control system changes the behavior of a physical process by observing its output and adjusting an input. A reference signal describes the desired behavior; a sensor reports a measurement; the error is the difference between the reference and measured output. The controller converts that error into an actuator command. In a robot, the controlled quantity may be position, heading, velocity, or a mechanism’s angle. The best controller depends on the dynamics and the quality of the measurements. Closed-loop control differs from open-loop control because the command is adjusted in response to observed behavior. Feedback can compensate for disturbances and model mismatch, but it can also amplify noise or create oscillations if designed poorly. A controller should therefore be evaluated as part of the complete loop: sensors, sampling, computation, actuators, mechanical plant, and the environment.

PID behavior and discrete implementation

A PID controller combines proportional, integral, and derivative terms. The proportional term responds to current error. The integral term accumulates error over time and can reduce persistent bias. The derivative term responds to the rate of error change and may add damping. In continuous form, u(t) = Kp e(t) + Ki ∫e(τ)dτ + Kd de(t)/dt. Digital implementations approximate these terms using sampled values and elapsed time. Implementation details can dominate performance. Integral windup occurs when accumulated error continues growing while the output is saturated. Derivative estimates can become noisy when measurements are noisy or sampling is irregular. A sudden change in target can cause a derivative kick depending on the chosen formulation. Output clipping, anti-windup behavior, reset conditions, unit consistency, and loop timing should be documented. Gains that work for one robot, mechanism, or sample interval should not be assumed to work for another.

Localization as state estimation

Localization estimates the robot’s state from imperfect observations. Wheel encoders provide incremental motion information; inertial sensors provide angular-rate and acceleration information; external systems may provide position or heading observations. Each sensor has a different error profile. Sensor fusion can improve estimates when measurement models, calibration, timing, and uncertainty assumptions are appropriate. Odometry integrates motion and consequently accumulates drift. Wheel slip and geometry error can create systematic bias; measurement noise can create random variation. Heading uncertainty affects the transformation of robot-relative motion into global coordinates. External observations can constrain drift, but can introduce latency, occlusion, calibration errors, or intermittent availability. A useful notebook records not only the estimated pose but also sensor timestamps, calibration parameters, and any confidence or covariance information the system exposes.

Calibration and controlled experiments

A good experiment isolates one source of error at a time. First verify sensor signs and units. Then test straight-line movement, rotations, and combined trajectories against a reference. Repeat each trial and report both central tendency and spread. If a parameter is adjusted, record its previous value and the reason for the change. Avoid changing several gains and geometry constants at once because the result becomes difficult to interpret. Useful measurements include steady-state error, rise time, settling time, overshoot, cross-track error, endpoint position error, and repeatability. Definitions should be stated explicitly. For instance, settling time requires a tolerance band around the target; without that band, two people may report different values from the same trace. The test surface, payload, battery condition, starting pose, and software version should be held constant where practical or recorded as covariates.

Graphs and interpreting results

A trajectory plot can show the reference path and estimated path in the same coordinate frame. A separate error-versus-time graph can reveal transient behavior hidden by the overall trajectory. Plotting control output can reveal saturation or abrupt changes. Each figure should include units, legend, sample interval, test conditions, and a clear indication of whether the data are simulated or measured. A plot made from synthetic data can demonstrate the format of an analysis but must be labeled illustrative. It cannot be cited as evidence that a real robot achieved a given accuracy. For real data, preserve the raw log and generate figures from a documented script. Report the number of trials and variability rather than selecting only the best run. If smoothing is applied, show or describe the method because filtering can conceal noise and alter apparent response time.

Failure modes and a repeatable workflow

Common problems include mismatched coordinate frames, sign errors, inconsistent units, stale sensor data, unexpected loop delays, actuator saturation, and calibration that changes after mechanical modifications. A controller may also appear unstable when the true issue is a faulty pose estimate. Debugging should therefore proceed from the measurement chain outward: confirm sensor data, validate the state estimate, check the control error, inspect the calculated command, and then verify actuator behavior. A repeatable workflow begins with a baseline, defines a single change, repeats the same test, and compares results using predefined metrics. Keep configuration files and logs alongside the code, while avoiding sensitive information. The next step for this notebook is to link the general theory to actual controller code and measured traces. The value of a control study lies not in a claimed “perfect tune,” but in a transparent explanation of the system, experiment, and evidence.

The first shows why implementation details dominate PID performance: with the actuator limited to ±1, an integrator that keeps accumulating during saturation (windup) drives the response far past the target, while the same gains with a clamped integrator settle cleanly. The plant is a first-order velocity lag integrated to position, discretized at 10 ms with explicit Euler, and the derivative acts on the measurement to avoid a kick at the step.

The second figure is about localization. If heading is the sum of small random errors, lateral position error is a sum of those errors weighted by remaining distance, so its variance grows as σ²·n(n+1)(2n+1)/6, roughly distance cubed, and the RMS error as distance1.5. The Monte Carlo curve follows the analytic one, and a heading source four times quieter shrinks the drift four-fold. That is the quantitative case for fusing a gyro with wheel odometry, and the reason I log timestamps and calibration constants alongside poses.
